# Project Proposal

## Tangible Coding Studio: Mission Builder

## Executive proposal

Tangible Coding Ltd will create a narrow WebMCP competition prototype that helps primary teachers design a feasible, screen-light tangible coding lesson with an AI agent. The teacher and agent work on one visible structured canvas; the website provides five explicit tools and the teacher retains final control.

## Why this project

The project is grounded in Tangible Coding's existing three-part model:

- physical resources;
- curriculum and teacher support;
- Tangible Coding Studio as the backstage planning and scaling layer.

The competition provides a short, evidence-producing route from concept to working Studio prototype. It does not require the team to build the complete commercial platform.

## User value

The prototype reduces the cognitive burden of turning a teaching goal into a physically feasible lesson. It combines:

- curriculum intent;
- available lesson time;
- class size;
- equipment inventory;
- grouping and participation;
- learner support;
- observable assessment.

## WebMCP value

WebMCP is integral rather than decorative. The site declares structured tools so the agent can work reliably with the current page state. The prototype demonstrates:

- shared human–agent context;
- visible changes;
- selective adaptation;
- deterministic validation;
- human-only approval.

## Competition fit

- WebMCP leverage: five non-trivial tools update structured UI state.
- Execution: one complete teacher journey reaches useful outputs.
- Potential impact: it solves a real planning problem for primary teachers.
- Creativity and ambition: it links agent-native web interaction to screen-light, physical classroom learning.

## Deliverable

A public desktop-first web application with:

- class and resource controls;
- structured lesson canvas;
- five WebMCP tools;
- pending-change review;
- deterministic validation;
- teacher-only approval;
- three printable outputs.

## Demonstration

The competition video uses one fictional P4 storytelling and debugging scenario. A single prompt drives the five-tool sequence. The teacher then reviews proposals, resolves validation issues, approves through the UI and opens the outputs.

## Work products

- Live application
- Public GitHub repository
- Open-source prototype code
- README and testing instructions
- Devpost project story
- Screenshots
- Public video under three minutes
- Post-submission learning review

## Constraints

- Deadline: 2026-09-03
- No real pupil data
- No full curriculum exposure
- No unlicensed supplier assets
- No autonomous approval
- No feature expansion beyond the Source of Truth

## Strategic value after the challenge

Even without a prize, the prototype can provide:

- the first working Tangible Coding Studio experience;
- evidence for Ian, schools, Business Gateway and funders;
- learning about teacher–agent interaction;
- reusable resource-aware validation logic;
- a clearer decision about the wider Studio roadmap.

## Decision requested

Approve the narrow prototype, company ownership and public release of limited authorised code and fictional sample content. Keep wider curriculum, trademarks, school data, commercial material and third-party assets outside the public licence.
