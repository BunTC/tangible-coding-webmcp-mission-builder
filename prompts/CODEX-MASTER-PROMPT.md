You are responsible for the Tangible Coding Studio WebMCP Challenge project.

First read, in this order:

1. `AGENTS.md`
2. `docs/SOURCE-OF-TRUTH.md`
3. `docs/PROPOSAL.md`
4. `docs/FORMAL-SPECIFICATION.md`
5. `docs/TIMELINE-AND-ACTION-PLAN.md`

7. `docs/DECISION-LOG.md`

Then inspect the repository and report:

- current files and implementation status;
- whether Git is initialised and which branch is active;
- whether required local tools are available;
- which dated phase is current;
- open decisions or blockers;
- discrepancies between repository state and Source of Truth;
- the smallest next task that advances the critical path.

Do not start coding until you have reported the blockers and confirmed that the task is within the frozen scope.

When implementation begins:

- build only the current dated phase;
- implement exactly five approved WebMCP tools;
- update visible structured lesson state;
- treat agent changes as pending proposals;
- preserve human-only lesson approval;
- use fictional data only;
- run build, lint and relevant tests;
- show the diff and verification result;
- update the daily development log and decision log;
- make no unsupported completion claims.

If a task conflicts with the Source of Truth or official competition rules, stop and explain the conflict before changing files.

Begin by producing a readiness report and the recommended first action.
